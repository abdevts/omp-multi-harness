# 04 — Claude Adapter (`src/agents/claude.ts`)

Target: Claude Code `2.1.274`. All Claude flags live in this file only.

## Availability

1. Resolve `claude.executable` (default `"claude"`) from PATH — no shell.
2. `<exe> --version` with a 5 s timeout; parse `<semver> (Claude Code)`.
3. Cache per process.

## Invocation — new session

```text
claude
  -p                                   # print / non-interactive; prompt from stdin
  --output-format stream-json
  --verbose                            # required alongside stream-json in -p (verify per version)
  --session-id <uuid-v4 generated by us>
  [--permission-mode plan]             # read-only runs
  [--tools Read,Grep,Glob]             # read-only allowlist
  [--add-dir <dir> ...]                # only when configured
```

- Working directory is set via the **spawn `cwd` option** — Claude Code has no `-C` flag.
- Prompt is written to **stdin**, then stdin is closed.
- `--model` omitted unless `claude.model` is configured.
- Never `--dangerously-skip-permissions` / `--allow-dangerously-skip-permissions`.

## Session id

We **generate** the UUID (`crypto.randomUUID()`) and pass `--session-id`, so the
OMP↔worker mapping is known before the process starts and survives a crash. This is the
key asymmetry with Codex (see 01 §5).

## Invocation — resume

```text
claude -p --output-format stream-json --verbose --resume <session-id> [--fork-session]
```

- `--fork-session` only when the caller explicitly branches.
- Resume failure → `SESSION_RESUME_FAILED`, then one automatic fresh-session retry with
  handoff context, `metadata.resumedFallback = true`.

## Read-only mapping

| requested | flags | `readOnlyEnforced` |
|---|---|---|
| `readOnly: true` | `--permission-mode plan` + read-only `--tools` allowlist | `true` |
| `readOnly: false` | default permission mode (or `acceptEdits` if `claude.acceptEdits: true`) | `false` |

Note: `plan` mode means Claude will produce a plan rather than edit. For a read-only
*review* this is the desired behavior; the mode preamble (02) tells it to report findings
rather than propose a plan for approval.

## Output parsing

`stream-json` emits one JSON object per line:

- `type: "system"` (init) → carries session id / model → verify it matches ours; on
  mismatch trust the CLI's value and record `metadata.sessionIdMismatch = true`.
- `type: "assistant"` / `"user"` → intermediate turns; used for progress only.
- `type: "result"` → terminal. `subtype: "success"` → `result` field is `output`.
  Other subtypes (e.g. error/max-turns) → `success: false` with the reported reason.
- Unparsable line → counted, debug-logged, ignored.

Fallback: if no `result` event is seen but exit code is 0, use the last assistant text.
If still empty → `INVALID_OUTPUT`.

`--include-partial-messages` is **not** used by default (token-level noise, no benefit at
our progress granularity). Configurable under `debug`.

## Version compatibility

Same pattern as Codex: `buildArgs(version, request)` + capability table
(`supportsStreamJson`, `requiresVerboseWithStreamJson`, `supportsSessionId`,
`supportsPermissionMode`). Unknown/newer → newest known set.
